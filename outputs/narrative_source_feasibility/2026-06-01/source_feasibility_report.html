叙事服务数据源可行性验证

生成时间：2026-06-01 | 角色：PM 前期探索 + Architect 边界校验 | 目标：先确认方向和可落地性，再交给 Developer 实现。

结论：叙事服务不能只靠新闻，也不能只靠社区热度。可靠路径是“四层数据源”：官方事实源、授权新闻源、公开研究/行业上下文、社区/社媒热度源。

开发闸门：Developer 只能接已经被 PM/Architect 标为 Can-Do、Paid Trial Ready 或 Controlled Pilot 的源。高风险爬虫、未审查 TOS/robots、登录/验证码/付费墙内容，不能直接进入开发。

一、分层判断

1. 可信事实源

公告、交易所/监管、公司 IR、政策文件、SEC/CNINFO 等。用于确认“这件事是否真的发生”。

优先开发

2. 授权新闻源

Tushare news、Wind/Choice/iFinD、LSEG/Reuters、RavenPack、Benzinga 等。用于发现“今天/最近发生了什么”。

先试用验证

3. 公开上下文源

财经门户、行业媒体、协会、部委、公司新闻页、RSS/sitemap。用于补上下文和线索。

合规爬虫试点

4. 社区/社媒热度源

股吧、雪球、Stocktwits、Reddit、X、微博。只当热度和候选叙事，不能直接当事实。

严格限制

二、轻量 Smoke 结果

源 结果 PM 判断
SEC EDGAR submissions API HTTP 200，约 1.24 秒，返回 Apple CIK 的 JSON，含 1000 条 recent filing metadata。 Can-Do，适合做全球/美股官方事实源。
Google News RSS HTTP 200，约 1.41 秒，A 股半导体查询返回 100 条 RSS item。 Can-Do，但只能当上下文和召回源，不是可信事实源。
Stocktwits public symbol stream HTTP 200，约 0.94 秒，AAPL symbol stream 返回 5 条 messages。 Controlled Pilot，只做美股社交热度。
GDELT DOC API HTTP 429，约 11.89 秒，返回限速提示：每 5 秒最多一次请求。 需要队列/缓存，不能直接交给 Developer 做高频请求。

四、Developer 闸门

  • 可以开发：SEC EDGAR、CNINFO 扩展、Google/Sina/STCN 的来源质量标签，前提是加上 source registry 和 trust tier。
  • 可以准备但不能直接上线：Tushare news 权限 smoke、iFinD/Choice/LSEG/RavenPack/Benzinga 的试用对接。
  • 只能试点：GDELT、Stocktwits、Reddit，必须限速、缓存、只当热度。
  • 暂时不要交给 Developer：雪球、股吧、微博、X 的非官方大规模抓取。

五、引用和依据

  • Tushare news 文档：`news` 接口需要单独权限，支持多主流新闻源和 6 年以上历史。
  • SEC EDGAR API 文档：REST JSON API，无需认证，filing metadata 实时更新。
  • CNINFO：A 股公告、深沪北交易所问询/监管/纪律处分等入口。
  • iFinD 数据接口 FAQ：支持 SDK/HTTP，正式/试用权限和 QPS 限制明确。
  • LSEG News API：提供 Reuters 和第三方新闻的授权 API 入口。
  • RavenPack News Analytics：提供实体、事件、情绪、相关性、新颖度和影响分析。
  • Benzinga APIs：提供新闻、分析师、电话会文字稿、Why Is It Moving 等金融 API 产品。
  • X API rate limits：recent search/full archive/search stream 有明确限额。
  • Reddit API 文档：listing/search API 有分页和 limit 约束。
