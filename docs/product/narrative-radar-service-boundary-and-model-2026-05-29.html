Narrative Radar 服务边界与时间序列模型

日期：2026-05-29

覆盖 Linear：MIK-80、MIK-81、MIK-82

结论

Narrative Radar 归属于 Narrative Service。FNI 后续可以消费 radar HTTP 响应并做展示或报告引用，但不能在 FNI 内部挖掘来源事件、计算 radar 分数、推断趋势状态，或修改 candidate/trusted narrative 状态。外部 provider 访问和 provider 归一化仍由 Gateway 负责。

已实现的服务契约

Endpoint用途边界
GET /api/v1/narratives/radar/contract 暴露 radar 归属、响应 envelope、score schema、降级元数据字段和时间序列模型。 只描述服务契约，不调用外部 provider。
GET /api/v1/narratives/radar/signals 从 seed/intake events 可重放生成 radar source signals 和 daily snapshots。 只读取 Narrative Service ledger，不写 negative cache。

Score Schema

公式版本为 radar-deterministic-v0。每个后续 radar score 必须暴露 deterministic 组件，而不能只返回 opaque heat number。

  • heat_score
  • trend_score
  • momentum_state
  • market_confirmation_score
  • evidence_quality_score
  • source_attention_components
  • window_start / window_end
  • baseline_window
  • formula_version
  • degradation_warnings

AI 以后可以用于证据摘要解释，但不能覆盖 deterministic scores，也不能改变 trust state。

Source-Signal Time-Series Model

Radar source signal 是 append-only ledger 的公共模型。每条 signal 绑定 source event、candidate narrative、实体抽取、时间戳、source weight、signal strength、evidence refs 和 provider metadata。

当前实现输出 daily snapshots，并在模型里声明 hourly/daily 两种粒度；后续加入 hourly window 时不改变 public API shape。
