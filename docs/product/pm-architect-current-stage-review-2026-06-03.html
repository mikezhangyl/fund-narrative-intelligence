关键发现

1. 产品壳已经能支撑下一阶段

outputs/product_shell/round8-current/ 下已有首页、artifact browser、route registry、config preflight、release manifest、acceptance checklist、source quality dashboard、workspace state/export 和 narrative data。当前 checklist 为 pass，release manifest 为 ok。

2. 真实叙事数据入口不是 live discovery

narrative_data.html/json 能把现有叙事、映射、证据包、质量审计和服务健康聚到一个入口，这是产品上的进步。但它的口径是 existing artifacts，不是实时采集今天全市场新叙事。

3. 来源质量 dashboard 的降级是合理信号

当前来源质量 dashboard status 为 degraded，这符合事实：SEC EDGAR 可以是 trusted fact，但公网媒体和社交/社区类来源仍然有 robots/TOS、节奏、禁止行为等风险。产品应该显示这些风险，而不是隐藏它们。

4. gateway 边界清楚

FNI 没有继续新增 SEC/CNINFO/news/social 直接采集适配器。这个方向必须保持：FNI 做消费、报告、探针和产品面；gateway 做外部采集、凭证、限速、缓存、标准化。

5. Fresh narrative digest 现在是 contract，不是生产 feed

fresh_narrative_digest 当前能输出候选状态、证据链接和 trust state，但仍是 candidate_untrusted 口径。它可以作为下一阶段 UI/工作流入口，不能作为可信实时叙事结论。

最大 caveat：Tushare news smoke 当前为 Blocked，原因是本地 gateway 请求被拒绝。这个不影响 demo release，但意味着 live news 入口还没有被本次复审接受。

下一阶段建议

  1. 补强 source-quality dashboard：每个 gateway source kind 都要有独立 coverage row。
  2. 把 fresh narrative digest 做成正式产品 surface，但所有未证实项保持 candidate_untrusted。
  3. 增加显式 live conformance lane：本地 release 不依赖凭证，live source check 作为 operator action 单独运行。
  4. 再往后进入 narrative drill-down、source-event timeline/search、review queue 和 workspace persistence 的深层工作流。

最终结论

接受当前阶段。当前 FNI 已经从“脚本和报告集合”进入“本地产品控制台 + artifact-backed 数据入口 + 来源质量治理”的阶段。下一步应进入 operator workflow 和 source-aware narrative review，而不是在 FNI 内继续扩外部数据源。
