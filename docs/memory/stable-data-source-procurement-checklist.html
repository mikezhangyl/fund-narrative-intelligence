稳定数据源采购与询价清单

面向 fund-narrative-intelligence 当前 A 股 / 国内基金优先路线，聚焦“稳定、正式、可持续”的数据来源，而不是继续依赖高波动网页接口。

中文 采购导向 A 股优先 基金研究优先 更新时间：2026-05-15
当前判断
东方财富体系里，真正值得询价的是 Choice 数据，因为这是官方正式的数据服务面。
天天基金当前公开可见的官方接口，主要是 小程序开放接口，更像业务集成能力，不像面向研究型 pipeline 的通用数据服务。

1. 我们现在要解决什么

数据层 当前主要问题 为什么需要正式源
holdings 当前依赖 Eastmoney 公开接口，稳定性和契约性有限 基金持仓是整条链路的入口，源不稳会拖垮后续所有层
market_quotes Eastmoney 行情接口出现远端断连，当前大量回退到 Yahoo 需要更稳定的 A 股行情主源，避免回退成为常态
valuation_snapshots 当前主要靠 Eastmoney 或 quote-derived 如果要提高结构化可信度，需要正式估值/行情衍生数据
financial_metrics 当前主要靠 Eastmoney F10 类页面接口 需要更稳定的财务指标源，避免页面改版风险
announcements CNINFO 已较稳定，但仍需确认是否需要统一商业源 如果商业源能补公告元数据、全文、历史覆盖，可提升一致性
fund data 基金净值、估算、基本信息、持仓等仍较分散 基金是我们的研究对象，基金层正式数据值得优先确认

3. 对 Choice 的询价清单

下面这份问题单，建议直接发给 Choice 销售或数据服务团队。

问题 为什么要问
是否提供程序化接口，而不只是终端？支持什么接入方式？ 我们需要接进 Python pipeline，不是人工看终端
基金持仓数据是否可程序化获取？支持历史持仓、季报持仓、Top holdings 吗？ 对应 holdings 主层
A 股日线/准实时行情是否可程序化获取？稳定 SLA 如何？ 对应 market_quotes，这是当前最痛点
估值指标是否覆盖 PE TTM、PB、总市值、流通市值、换手率等？ 对应 valuation_snapshots
财务指标是否覆盖营收同比、净利润同比、ROE、毛利率、现金流等？ 对应 financial_metrics
公告数据是否包含公告元数据、正文链接、PDF、历史回溯？ 对应 announcements / announcement_evidence
基金净值、净值估算、基金基本信息、基金规模、基金经理数据是否可拿？ 基金是研究对象，不只是持仓入口
新闻或研报是否有正式数据服务？是否能合法用于内部研究系统？ 对应后续 news_evidence 扩展
价格模式是什么：按终端、按账号、按接口、按并发、按字段还是按年包？ 需要评估成本结构
是否有试用、沙箱、样例文档、字段字典？ 避免先采购再踩集成坑
是否允许内部研究系统落地缓存、归档、衍生分析？授权边界是什么？ 涉及合规和长期可运营性

4. 对天天基金的确认清单

这里不是默认采购，而是先确认它到底有没有研究型数据合作面。

问题 为什么要问
除了小程序开放接口，是否有面向机构/研究系统的正式数据接口？ 这是最关键的判断问题
是否提供基金持仓、基金净值、基金基本信息、历史变更的 API？ 这是我们最可能从天天基金获益的层
是否提供基金估算、规模、基金经理、费率、申赎状态等结构化字段？ 有助于基金侧画像增强
是否提供商业合作接口文档、字段字典、稳定性说明？ 公开小程序接口不等于研究级接口
价格模式是什么？是否有企业合作或研究数据授权？ 需要确认是不是可采购产品
如果没有研究级 API，是否至少能确认哪些网页/接口可长期稳定访问？ 即便不能买，也要知道它能否作为低风险公开源

5. 按我们系统六层需求的询价映射

系统层 优先问 Choice 再问天天基金 备注

fund meta 是 是 基金基础信息可能两边都值得问

6. 我们的采购判断标准

  1. 是否是正式商业产品，而不是灰色网页接口。
  2. 是否支持程序化接入，而不只是人工终端。
  3. 是否覆盖我们最痛的三层：holdings、market_quotes、financial_metrics。
  4. 是否给字段字典、样例、授权边界、SLA 或稳定性说明。
  5. 价格是否能接受，且成本结构适合长期运行，而不是只适合单人终端使用。

7. 当前最务实的结论

  • 如果你现在就要找“稳定主源候选”，优先联系 Choice。
  • 天天基金要问，但要先确认它到底有没有“研究型/机构型数据接口”，不要默认它一定有。
  • 在正式源到位之前，当前 Eastmoney 网页接口仍然只能算过渡方案，不适合当长期稳定底座。
